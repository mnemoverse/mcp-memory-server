# Mnemoverse memory discipline

A memory server is connected. Connecting it does not make it useful by itself; these standing rules do.

## Recall before acting

Read memory before: starting work on a project you have touched before, choosing a library or pattern, writing tests or commits where conventions apply, answering "how do we usually do X here", and anything phrased as "again" or "like last time". Search with the user's actual words plus the project name. If the first search returns nothing useful, try one broader query, then proceed without memory rather than looping.

Do not recall for one-off factual questions or anything fully specified in the current message.

## Save after deciding

Write to memory when: a decision was made that will still matter next week, the user corrected you (the strongest signal there is), an approach failed and you know why, a preference was stated that outlives this task, or a fact about the environment was discovered the hard way. One memory, one fact.

Do not save: file contents you can read again, restatements of the task, transient state, or anything containing secrets, tokens, or personal data. Never store secrets regardless of backend.

## Keep the past intact

When something changes, the old fact is not wrong, it is closed. Mark it superseded and write the new one alongside; deleting it destroys the explanation for old work. If recall returns two entries that disagree, surface both with their dates instead of silently picking the closer match.
